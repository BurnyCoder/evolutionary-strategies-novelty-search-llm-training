# Preregistration: first paired ES pilot

Author: Libor "Burny" Burian. Registered 2026-11-07, before any model execution. The first GitHub commit containing this file and [data manifest](../data/manifest.json) is the public registration record. Later changes must be append-only amendments with reasons and timing relative to observed results.

## Question and falsifiable hypothesis

Does adding correctness-gated historical semantic novelty to full-weight ES improve held-out greedy Countdown accuracy over reward-only ES with matched perturbations, prompts, and generation count?

H1 (conditional, pilot): final main-method accuracy minus final reward-only accuracy is positive for seed 0 on the registered test distribution. A difference at or below zero falsifies the directional prediction for this pilot. A paired 95% problem-bootstrap interval wholly above zero supplies conditional evidence; an interval spanning zero is inconclusive. Even a positive interval is not evidence of seed robustness. Larger novelty values alone do not confirm H1. Hardware or generation failure establishes neither superiority nor inferiority; incomplete conditions are labeled as such.

## Frozen configuration and data

[configs/pilot.json](../configs/pilot.json) records model and embedding revisions, the upstream ExTra commit, seed, perturbations, and all initial settings. The [manifest](../data/manifest.json) fixes dataset hashes. The data-generation code precedes model execution. Training/validation/test contain respectively 8192/512/2048 solvable problems, each half three-number and half four-number; 1024 five-number problems form a separate harder-distribution test.

Number multisets are globally unique across all examples, not merely split labels. Numbers are sampled from integers 1 through 50; random arithmetic trees are retained when their root is an integer target from 1 through 999. Intermediate rational and negative values are allowed. This produces a witnessed, non-uniform distribution of solvable problems. The target's witness never enters the model prompt. All constants must match supplied numbers exactly; AST allowlisting and rational arithmetic grade 1 for correct, 0.1 for legal/wrong, 0 for invalid. Multiple answer tags are invalid. One answer tag can be extracted from surrounding prose; a bare expression is also accepted. Neither validation nor test prompts may be used to generate training updates or archive entries.

Sixteen training probes are selected by a seeded permutation. A deterministic cyclic schedule over the other training examples supplies 32 rotating problems per generation; all candidates and both conditions receive the same 48 prompts. At epoch boundaries the pool is reshuffled deterministically. Fixed probes contribute to fitness but are evaluated separately in reports. A fixed validation subset of 64 is logged every five generations and at the final generation; validation does not select checkpoints or alter hyperparameters.

## Intervention and control

Both conditions start from the pinned base weights. Thirty independent Gaussian full-weight perturbations use sigma 0.001. Average centered ranks (range -0.5 to 0.5) multiply noise in the update `theta += (0.0005/30) * sum(rank(F_i) * epsilon_i)`. This effective coefficient absorbs inverse sigma. All-equal fitness yields zero update. FP32 CPU masters reconstruct BF16 inference candidates afresh, including all unique parameter tensors and updating tied weights once. No gradient optimization is used.

Main fitness is mean task reward across all 48 responses plus 0.25 times mean novelty across the 16 probes; control fitness is mean task reward alone. Both generate and embed identical numbers of probe responses. MiniLM embeddings are normalized; for each correct answer novelty is one minus the maximum cosine similarity to correct history or other correct candidates for that probe, excluding itself. For an empty reference pool, maximum similarity is zero. Incorrect answers receive zero novelty. Cosines are clipped to [-1, 1] solely for numerical roundoff; no extra group scaling or warmup is used. Historical memory remains frozen during scoring; correct responses are then seed-shuffled per probe, appended, and the latest six retained. The Boolean correctness gate never derives from positive reward. Prefix regeneration is excluded. This is an [ExTra](https://arxiv.org/abs/2606.24994) adaptation, not reproduction; see [audit](../docs/literature.md).

## Twelve-hour timing rule

Dependency setup, literature review, data construction, registration, tests, core-code publication and downloads occur before the clock. The persisted wall-clock start and absolute deadline are created immediately before GPU calibration/model loading. Downtime and restarts count against the same allowance. Phase maxima are one hour calibration/original evaluation, 4.5 hours main, 4.5 hours reward-only, and two hours final evaluation/report preparation. Early finishes may shorten total duration; no phase gains time by resetting its clock. Publication transfer after the experiment may finish later, but results record the deadline and unfinished artifacts honestly.

Calibration measures three candidate evaluations on training prompts, one full 30-noise update, an atomic full checkpoint, and one 64-problem validation. Estimate generation seconds as `30 * max(candidate_seconds) + update_seconds + checkpoint_seconds + validation_seconds/5`. Freeze common `G = min(500, floor(0.8 * 16200 / estimated_generation_seconds))` before training. Reject G < 1 as infeasible. The calibration model is discarded and original weights are reloaded; calibration does not become an extra training generation.

Start with inference batch 16. Only on out-of-memory errors, retry with 8, 4, 2, then 1, clearing temporary state and logging each failure; freeze the successful batch before timing candidates. No accuracy-driven calibration choices. Both conditions use the same batch. Greedy responses are capped at 128 new tokens. A fixed safe memory-only batch reduction, if needed later, must be logged as a deviation and applied to both conditions' remaining evaluation; exact floating-point equivalence across batch sizes is not asserted.

Baseline greedy and sampled evaluation is attempted within the first hour. Missing baseline work is completed in the final evaluation allowance, identified in the phase log. Each trained condition stops at its earlier phase or absolute deadline. Only fully completed generations count; atomic checkpoints and resumable candidate records prevent counting partial updates as completed training. If a run cannot finish G, retain its last complete checkpoint as a secondary partial result; do not call it the registered final endpoint. Do not change seed or silently lower G after freezing it.

## Endpoints and analysis

Primary: final scheduled checkpoint greedy exact accuracy on all 2048 test problems, main minus reward-only, with original-model accuracy alongside. Evaluation runs after training, not checkpoint selection. Secondary: harder-distribution accuracy, validity, mean reward, fixed-probe accuracy, train/evaluation elapsed time, generated token counts, and correct canonical expression-tree counts. Canonicalization sorts children of addition and multiplication only; this is syntactic diversity, not algebraic equivalence or a reliable semantic metric by itself.

A seed-fixed random subset of 256 test problems receives 16 independent sampled responses per model with temperature 1 and top-p 1. Use the standard unbiased pass@k estimator `1 - C(n-c,k)/C(n,k)` for k=1,8, n=16, rather than counting whether any arbitrary first eight succeed. Source: [Evaluating Large Language Models Trained on Code](https://arxiv.org/abs/2107.03374). Generation sampling seeds and problem/sample order are fixed across conditions. Sampling uses all-token support (top-k disabled). Full prompts and responses are logged.

Use 10000 paired bootstrap resamples of test problem IDs, seed 20261107, percentile 95% intervals for the primary accuracy difference and descriptive accuracy intervals. Resample each problem's outcomes together across methods. Report unadjusted secondary analyses as descriptive, without multiple-comparison significance claims. No training-seed uncertainty is estimated. A missing/incomplete primary condition prevents a confirmatory pilot comparison. No exclusion based on answer quality; invalid responses are failures. Technical failures, missing rows, truncation, and retry counts are reported.

## Reliability, resources, and reporting

Checkpoint each generation atomically with FP32 master weights, Python/NumPy/Torch/CUDA RNG state, archive and shuffle RNG, prompt cursor, counters, exact config, dataset hashes, code revision, frozen G and absolute deadline. Candidate progress files support restart within an unfinished generation. Loading a checkpoint validates its configuration and restores the original time budget. CUDA/kernel/library changes can break bit-level reproducibility; record the environment and test deterministic reconstruction on the actual device.

Stream untruncated JSONL prompt/response events to disk and stdout. A localhost dashboard shows accuracy, reward, novelty, validity, throughput and checkpoint state. One report command reads artifacts and generates tables/plots, Markdown reports, model-card content, static interactive results, and the PDF paper. All empirical numbers originate in those artifacts. Publish negative findings and incomplete evaluations, not empty cells implying success. Model exports preserve original tied-weight configuration and tokenizer.

## Amendment A: source-aligned weighting before either trained condition

2026-11-07. This append-only amendment supersedes the centered-rank weighting and coefficient in the original intervention section above. It follows the user's request to prefer the source algorithms unless a deviation has a convincing performance rationale. The original registration remains visible. Calibration and part of original-model evaluation have already occurred and their outputs were visible; neither trained condition has begun. This is therefore an amendment before training, **not** a registration made before all model results. The change is motivated by the source equations, not by a comparison of trained outcomes.

Let `Q_i` remain mean task reward over the scheduled responses and `N_i` remain mean correctness-gated probe novelty. Define `Z_i = (Q_i - mean(Q)) / (std_population(Q) + 1e-8)`, with an explicit zero vector for constant quality. Use `W_i = Z_i + gamma * N_i` for the main condition and `W_i = Z_i` for reward-only. Update `theta += (alpha / population) * sum(W_i * epsilon_i)`, without a second normalization, centering, or ranking of `W`. Use `gamma = 1.0`, ExTra's reported default, in these normalized-quality units. There is no claim that this coefficient is optimal for ES. All-equal quality gives zero **quality** update; a positive common novelty bonus remains present in the main update, as required by post-normalization addition.

The source basis is [ES at Scale Algorithm 2](https://arxiv.org/html/2509.24372v3#S3), its pinned [reward-shaping source](https://github.com/VsonicV/es-at-scale/blob/574a9d134da1ffce2a8bb812019899e5c96b588a/es_at_scale/utils/reward_shaping.py), and [ExTra Equation 2, Appendix D.1, and Table 7](https://arxiv.org/html/2606.24994v1). Centered ranks have established ES precedent, but there is no task-specific evidence here that discarding reward magnitudes or normalizing the combined signal is better. ExTra explicitly motivates adding novelty after normalization so it does not alter task normalization statistics. Applying that ordering to population-level ES coefficients remains a new combination; ExTra's GRPO-specific guarantees do not automatically transfer.

Retain independent per-tensor Gaussian streams, FP32 masters and fresh BF16 reconstruction. These implement the isotropic Gaussian equation and prevent restoration drift; they differ from the upstream worker's correlated layer streams and native-precision arithmetic. Retain the paper-specified correct-response memory, rather than inserting incorrect responses as the released embedding-memory helper permits. Prefix regeneration and GRPO remain outside this ES experiment. Dataset, prompts, seed, perturbations, evaluation, endpoints, frozen generation count and absolute deadline are unchanged. The calibration workload is retained: weighting scalar coefficients does not change the measured full population/noise reconstruction workload. The discarded calibration model is never used to initialize training.

The run record must preserve the original configuration/revision and add the amended configuration, publication revision, reason, timing and unchanged absolute deadline. Both trained arms start from original pretrained weights under this amendment. Resume must refuse a weighting change once either trained condition has a checkpoint. Publish the amendment and tested implementation before restarting model execution.
